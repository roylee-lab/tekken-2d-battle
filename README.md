# TEKKEN 2D BATTLE — GLOBAL CHAMPIONSHIP EDITION

브라우저에서 바로 즐기는 2D 격투 게임. 설치 없이 `index.html` 하나로 동작합니다.

## 특징
- 17명의 캐릭터 (히든 캐릭터 Tirón 포함, 신캐 영탁·허도개미·차니팍·이유동), 나라별 스테이지 13개
- CPU 난이도 6단계: 매우 쉬움 · 쉬움 · 보통 · 어려움 · 매우 어려움 · LUNATIC
- 히든 보스 '흑요': 난이도 LUNATIC → CPU 대전 선택 화면에서 B (2페이즈 · 페이즈당 체력 200 · 절대 결계 · 플레이어 부활 2번)
- 체력 2배(경기 시간 증가), 쿨타임은 라운드가 바뀌어도 이어짐
- 모든 캐릭터 Q/W/E/R 스킬 + 패드립 배틀(글자 먼저 누르기) · 초크 연타 탈출 · KC 연타 등 미니게임형 스킬
- 3판 2선승, 99초 타이머, 콤보·히트스톱·아나운서 음성
- 나라별 오리지널 칩튠 BGM (Web Audio로 실시간 합성)
- CPU 대전, 캐릭터 도감, 승리 기록
- 온라인 대전: 방 코드 / 같은 와이파이 자동 매칭 (WebRTC, PeerJS)
- 로그인(닉네임+비밀번호) · 친구 추가 · 친구에게 대전 신청
- 모바일 터치 조작 지원

## 서버 (로그인 · 친구)
- Vercel 프로젝트에 **Upstash Redis**(Vercel Marketplace)를 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN` 환경변수가 자동으로 생기고 `api/game.js`가 이를 사용합니다.
- 비밀번호는 scrypt로 해시해서 저장하고, 로그인 시도는 횟수 제한이 걸려 있습니다.
- 접속 상태는 게임이 몇 초마다 서버에 신호를 보내서 표시합니다. 실제 대전 연결은 PeerJS(WebRTC)로 기기끼리 직접 합니다.


## 온라인 연결 수정 (2026-10-25)
- `api/rtc.js`가 같은 사이트 HTTPS로 WebRTC 접속 정보를 교환합니다. 기존 Upstash 환경변수를 그대로 사용합니다.
- PeerJS 공용 WebSocket이 차단돼도 방 코드/친구 초대로 접속 정보를 교환할 수 있습니다.
- 자동 매칭의 네트워크 구분도 같은 사이트에서 계산하며 외부 IP 조회 서비스를 호출하지 않습니다.
- 임시 방/SDP는 180초 뒤 만료됩니다. 연결 후 게임 프레임은 Redis를 거치지 않습니다.
- `WEBRTC_ICE_SERVERS`에 ICE 서버 배열(JSON)을 지정하면 자체 TURN/STUN 구성을 사용할 수 있습니다.
  설정하지 않으면 기존 게임에 포함돼 있던 PeerJS 기본 STUN/TURN 구성을 유지합니다.
- 학교/공유기의 기기 격리 또는 UDP 차단 환경에서는 동작하는 TURN 중계가 필요합니다.
  HTTPS 신호 교환 성공만으로 모든 네트워크에서 직접 통신이 보장되는 것은 아닙니다.
- 같은 공인 IP를 사용하는 네트워크를 자동 매칭 대상으로 봅니다. IPv4/IPv6/VPN에 따라
  같은 와이파이여도 구분될 수 있으며, 이때는 방 코드를 사용합니다.
- 방향 갱신은 지상/공중/공격 상태 모두 적용하며 충돌 처리 후 두 캐릭터가 동시에 상대를 봅니다.

검증: `node tests/regression.mjs`.
로컬 통합 검증은 `tests/local-server.mjs`의 임시 저장소를 사용합니다(실제 계정 DB 미사용).
`tests/browser.cjs`는 개발 환경의 Playwright 및 Chrome을 사용합니다.


## TURN 중계 서버 (2026-10-25 추가)
- 서로 직접 연결이 안 되는 네트워크(공유기 기기 격리, 모바일 데이터, 회사·학교망)를 위해 Cloudflare Realtime TURN을 지원합니다.
- Vercel 환경변수 `CF_TURN_KEY_ID`, `CF_TURN_API_TOKEN`을 넣으면 `/api/rtc`가 24시간짜리 임시 TURN 자격증명을 발급합니다 (키는 서버에만 보관).
- 우선순위: `WEBRTC_ICE_SERVERS`(직접 지정) → Cloudflare TURN → 기본 STUN.

## 온라인 접속 안정화 (2026-10-25 밤)
원인 분석 결과:
1. **중계(TURN) 없음**: 직접 연결이 막힌 네트워크(모바일 데이터, 학교/회사 와이파이)끼리는 연결 불가 → TURN 설정 필요 (Metered 무료 플랜은 카드 없이 가능).
2. **방장이 다른 앱(카톡 등)에 가면** 브라우저가 멈춰서 방장이 접속 요청을 못 받음 → 참가자가 30초 만에 포기하던 문제.
3. **한 번 실패하면 방이 통째로 닫힘** → 재시도 불가.
4. **죽은 PeerJS TURN 주소**가 기본 설정에 남아 있었음 (DNS 조회 실패).
5. **Upstash 무료 한도(월 50만 명령)**: 친구 목록 확인이 5초마다 8개 명령을 써서 오래 켜 두면 한도를 넘을 수 있음 → 서버가 꺼지면 방 만들기도 실패.
6. 같은 와이파이 매칭이 IPv6 주소(기기마다 다름)에서 서로를 못 찾음.

수정:
- 참가자는 방장 응답을 최대 2분 기다림, 방장은 화면이 돌아오면 즉시 확인. 방은 10분 유지(자동 연장).
- 연결 실패 시 방은 유지하고 자동 재시도(최대 3번), 실패 원인을 화면에 구체적으로 안내.
- 서버(DB)가 안 되면 PeerJS 공용 서버로 자동 전환.
- 죽은 TURN 제거, ICE 수집 대기 7초 → 3.5초.
- 친구 목록 확인 간격 조절 + 명령 수 절감 (로그인 정보에 닉네임 포함).
- 같은 와이파이 대전: 같은 공유기(IPv6는 앞 64비트)에서 열린 방 목록에서 골라 참가, 없으면 내가 방을 열고 목록에 올림. 방 코드로도 참가 가능.
